# ספק SMS לקוד האימות בפורטל — החלטה פתוחה (15/10/2026)

הערוץ הראשי לקוד האימות עובר ל-SMS; וואטסאפ (Green API, הערוץ היחיד עד כה)
נשאר כגיבוי ידני — כפתור "שלח בוואטסאפ במקום" ב-`/portal/login`.
**שום דבר כאן לא פעיל עד שרונן בוחר ספק, פותח חשבון ומוסיף את משתני הסביבה.**
בלעדיהם `isSmsConfigured()` (`src/lib/portal/otpChannel.ts`) מחזיר `false`,
וכל שליחה/שליחה-חוזרת ממשיכה לצאת בוואטסאפ בדיוק כמו היום.

## שלושה ספקים ישראליים מקומיים (לא ראוטים בינלאומיים)

נבדקו מול התיעוד הפומבי שלהם (15–16/10/2026) — **אף אחד מהם לא מפרסם מחיר
להודעה בעמוד ציבורי**; זה נפוץ אצל ספקי SMS עסקיים ישראליים — צריך לפנות
למכירות/להירשם כדי לקבל הצעת מחיר אמיתית.

### 019 SMS (`019sms.co.il`)
- תיעוד API: https://docs.019sms.co.il/sms/send-sms.html
- `POST https://019sms.co.il/api`, גוף JSON או XML, שורש `sms`.
- שדה שולח (`source`): עד 11 תווים, ספרות ואותיות אנגליות בלבד, בלי `+`.
- יעד (`destinations.phone`): `5xxxxxxx` או `05xxxxxxx`.
- תמיכה ב-OTP ייעודי מוזכרת בעמודי השיווק (שדה `tag` לקידומת כמו `#` לאימות
  גוגל), אבל התוכן המלא לא פורסם בציבור.
- **פער בתיעוד שנמצא:** העמוד הציבורי לא מציג שדה סיסמה/טוקן — רק
  `user.username`. זה חריג ביותר לספק SMS (כולם דורשים אימות חזק יותר
  מ-username בלבד) — כמעט ודאי שחסר כאן שדה (`user.password` או API key
  בכותרת) שפשוט לא נתפס בסריקה הפומבית. **אל תסמכו על הדוגמה הזו כחוזה
  סופי** — יש לאמת מול חשבון אמיתי/sandbox לפני חיבור.
- קו מכירות: 055-999-99-00 (מהעמוד השיווקי).

### InforU (`inforu.co.il`)
- תיעוד API (PDF, גרסה 6.1, 2020): https://www.inforu.co.il/wp-content/uploads/2020/12/SMS_API-6.1.pdf
- `POST https://api.inforu.co.il/SendMessageXml.ashx`, אימות עם username +
  טוקן API מהגדרות החשבון, קידוד UTF-8.
- שדה שולח: עד 11 תווים לטיניים רצופים (בלי רווחים) **או** 14 ספרות (בלי
  אותיות) — שם שולח מותאם-אישית לפעמים כרוך בעלות הקמה חד-פעמית.
- תמחור מדורג: חבילה גדולה יותר = מחיר נמוך יותר להודעה (לפי עמוד
  "חבילת SMS" של האתר) — אין מספר מפורסם.
- המערכת גם מפרסמת ערוץ "OTP" ייעודי בנפרד מה-SMS הרגיל — שווה לשאול אם זה
  המוצר הרלוונטי במקום ה-API הכללי.
- התיעוד מ-2020 — לוודא שהוא עדיין מדויק מול התמיכה לפני חיבור.

### GlobalSMS (`globalsms.co.il`)
- עמוד המוצר: https://globalsms.co.il/sms-api-israel.html — דף שיווקי, לא
  תיעוד API מלא; לקבל את המפרט המלא והמחיר רק אחרי הרשמה/פנייה.
- `POST https://api.globalsms.co.il/v1/send-sms`, גוף JSON
  (`Content-Type: application/json; charset=utf-8`).
- אימות: הדוגמה בעמוד שולחת **גם** `Authorization: Bearer YOUR_API_KEY`
  בכותרת **וגם** `"apiKey": "YOUR_API_KEY"` בגוף — העמוד לא מבהיר איזה
  מהשניים השרת בפועל דורש. **לאמת עם הספק לפני חיבור**, בדיוק כמו הפער
  אצל 019 SMS למעלה.
- שדות הדוגמה: `sender` (שם שולח — הדוגמה "GlobalSMS", **בלי** מגבלת
  אורך/תווים מצוינת בעמוד), `recipients` (מערך, הדוגמה `05XXXXXXXX` — בלי
  קידומת מדינה, בלי כללי פורמט פורמליים), `message`, `encoding`
  (הדוגמה `"UTF-8"`). העמוד לא מסמן אף שדה כחובה/אופציונלי במפורש.
- תשובת ההצלחה/כישלון, קודי שגיאה — **לא מתועדים בעמוד כלל**.
- בדיקת סטטוס מסירה מוזכרת כקיימת ("ניתן לבדוק אם ההודעה הגיעה למכשיר")
  בלי endpoint או פורמט.
- מחיר: הקישור "מחירון SMS" מוביל לאותו עמוד הרשמה כמו "פתיחת חשבון"
  (`campaigns/sms.html?sa=1`) — לא ברור אם זה תמחור self-serve או מותנה
  בפנייה; יש גם קישור "צרו קשר" נפרד.
- **הסתייגות:** זהו דף שיווקי בלבד (זמני אספקה/זמינות/כיסוי — הצהרות
  שיווק בלי SLA מפורסם), לא מסמך API — ולא נמצאו דרישות רישום שם שולח או
  מגבלות OTP ייעודיות. לקבל את התיעוד המלא והמחיר האמיתי מהספק ישירות
  לפני כל חיבור.

### ספק רביעי שנבדק בקצרה, לא מומלץ כברירת מחדל: SMS4Free (`sms4free.co.il`)
לא נמצא תיעוד רשמי פומבי על מחיר או שם שולח — רק קליינט PHP צד-שלישי
(`edenohana/sms-free-php`). כנראה זול/קל יותר להרשמה עצמית, אבל בלי אימות
ישיר מול האתר עצמו אי אפשר לדעת את תנאי האימות/שם השולח.

## מה צריך ברגע שרונן בוחר ולהיפתח חשבון
1. פרטי החשבון (username/API key, שם שולח רשום) → ערכים אמיתיים ב-`/etc/billing/billing.env`
   בלבד — **לא** בקוד ולא ב-`.env.example` (שם רק `.env.example`).
2. `SMS_PROVIDER` (שם הספק), `SMS_API_KEY`, `SMS_SENDER` — שלושתם ב-`src/env.ts` כבר מוגדרים (ראו שם).
3. מימוש ה-adapter הקונקרטי ב-`src/lib/portal/sms.ts#sendSms` — פונקציה אחת,
   מאומתת מול ה-sandbox/חשבון האמיתי של הספק לפני השליחה הראשונה בפרודקשן.
4. `isSmsConfigured()` יהפוך ל-`true` לבד ברגע שני המשתנים קיימים — שום
   שינוי קוד נוסף לא נדרש כדי שהברירת מחדל תעבור ל-SMS.

## פורמט הודעת ה-SMS (WebOTP)
הקוד בשורה משלו, ושורה אחרונה **בדיוק** בפורמט ש-Chrome's WebOTP API מצפה
לו: `@<domain> #<code>` — ה-`domain` חייב להיות זהה ל-origin שממנו הדפדפן
קורא ל-`navigator.credentials.get()`, אחרת אין אוטופיל, בלי שגיאה גלויה.
נגזר אוטומטית מ-`APP_URL` (`src/lib/portal/otpChannel.ts#webOtpDomain`) —
לא ערך קבוע בקוד — כדי שהוא תמיד יתאים לכתובת שבה הפורטל באמת מוגש
(כרגע `almog-haifa.co.il` בפרודקשן, דומיין אחר ב-staging).
